## 3. Описание проблемы
При описании архитектуры проектируемой системы крайне важно придерживаться индустриальных стандартов во всем: 
- в нотации моделирования, 
- в шаблонах архитектурной спецификации, 
- в методике проектного управления.

Без всех этих усилий (то есть усилий в области инженерной культуры) техническая документация неизбежно превратится в набор бессвязных диаграмм, текстов и других артефактов, которые, если и описывают состояние системы, то уж наверняка делают это фрагментарно и противоречиво.
Однако проще сказать, чем сделать: внимательное и тщательное следование стандартам требует  высоких концентрации, мотивации и эрудиции.

Система **ArcEpigram** должна сама руководить пользователями (архитекторами, аналитиками и т.п.), заставляя их придерживаться (зачастую неявно) выбранного SDLC.
Например, если для разработки нового проекта были выбраны
- ARC42 - стандарт архитектурной спецификаии, 
- C4 - графическая нотация 
- Scrum - методология проектного управления,

то  **ArcEpigram** будет ставить пользователю конкретные задачи в контексте этих опций:
- Определить технические и огранизационные ограничения (ARC42),
- Определить цели качества системы (ARC42),
- Описать системный контекст (ARC42 + С4),
- и т.п.

Таким образом,  **ArcEpigram** проводит пользователя по нужным разделам архитектурной спецификации,  в нужном порядке, проверяя ее на целостность и непротиворечивость, обеспечивая трассируемость всех разделов и диаграмм.

Допустим, **ArcEpigram** будет назначать пользователю (согласно его роли в проекте) рабочие задачи (как с СЭД), которые таким образом обеспечат контекст и границы для конкретных действий по описанию архитектуры.
Такие задачи легко отслеживать, контролировать, переназначать на других пользователей и привязывать к внешним трекерам.

Другой (альтернативный) способ управления пользователем - автоматические подсказки, наводящие и уточняющие вопросы, напоминания - все это может интерактивно генерироваться AI-ассистентом.
